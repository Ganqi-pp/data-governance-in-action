# 指标口径字典

> 指标口径不统一，是数据治理里最容易被低估的问题：同一个“活跃率”，业务、技术、报表各算各的，开会先吵半小时。
> 本项目把 5 个核心指标的口径、SQL、Owner、注意事项固化在 [`config/metrics.json`](../config/metrics.json)，看板与报告共用同一份 SQL。

## 2. 指标定义

### 2.1 市场主体总数（MKT-TOTAL）

- **定义**：截至数据截止日，登记状态为存续或在业的市场主体户数。
- **公式**：`COUNT(*) WHERE status IN ('存续','在业')`
- **SQL**：

```sql
SELECT COUNT(*) AS value
FROM dwd_market_register
WHERE status IN ('存续','在业');
```

- **口径说明**：注销、吊销、迁出不计入；隔离数据不计入，单独披露。
- **使用场景**：区域市场主体规模、月度通报。
- **注意事项**：不要用“全部登记主体数”替代，否则会把已注销企业算进来。

### 2.2 市场主体活跃率（MKT-ACTIVE）

- **定义**：存续或在业主体占全部登记主体的比例。
- **公式**：`存续或在业户数 ÷ 登记主体总数 × 100%`
- **SQL**：

```sql
SELECT ROUND(100.0 * SUM(CASE WHEN status IN ('存续','在业') THEN 1 ELSE 0 END) / COUNT(*), 2) AS value
FROM dwd_market_register;
```

- **口径说明**：分母为治理后全部主体；分子只含存续/在业。
- **使用场景**：营商环境分析、区域活力比较。
- **注意事项**：不同地区对“在业”的定义可能不同，跨区域比较前先对齐码表。

### 2.3 A 级信用企业占比（CRE-A）

- **定义**：信用等级为 A 的企业占有效信用评价企业的比例。
- **公式**：`credit_level='A' 的记录数 ÷ credit_level 非空记录数 × 100%`
- **SQL**：

```sql
SELECT ROUND(100.0 * SUM(CASE WHEN credit_level = 'A' THEN 1 ELSE 0 END)
             / NULLIF(COUNT(credit_level), 0), 2) AS value
FROM dwd_credit_rating;
```

- **口径说明**：等级缺失的记录不进入分母；同一企业多次评价时，当前实现按记录数计算，生产环境应按“最新一次评价”去重。
- **使用场景**：信用监管、分级分类监管。
- **注意事项**：这是本项目的一个简化，已在“已知边界”中说明。

### 2.4 企业诉求办结率（CASE-CLOSE）

- **定义**：状态为已办结或已回访的工单占全部工单的比例。
- **公式**：`(已办结 + 已回访) ÷ 工单总数 × 100%`
- **SQL**：

```sql
SELECT ROUND(100.0 * SUM(CASE WHEN status IN ('已办结','已回访') THEN 1 ELSE 0 END) / COUNT(*), 2) AS value
FROM dwd_complaint_case;
```

- **口径说明**：只统计已关联市场主体的工单，匿名工单单独统计。
- **使用场景**：政务服务考核、诉求办理复盘。
- **注意事项**：办结不等于满意，需与满意度结合看。

### 2.5 平均满意度（CASE-SAT）

- **定义**：已回访工单中，企业给出的 1—5 分满意度的算术平均值。
- **公式**：`AVG(satisfaction) WHERE satisfaction BETWEEN 1 AND 5`
- **SQL**：

```sql
SELECT ROUND(AVG(satisfaction), 2) AS value
FROM dwd_complaint_case
WHERE satisfaction BETWEEN 1 AND 5;
```

- **口径说明**：无效评分（0、6、非数字）不参与均值。
- **使用场景**：服务质量评估。
- **注意事项**：未回访工单为空，不应当作 0 分；样本量小时需看置信区间。

## 3. 口径管理规则

1. **一指标一口径**：同一指标只允许一个权威口径，派生指标必须引用原子指标；
2. **业务提口径、数据写 SQL、双方签字**：Owner 对定义负责，Steward 对实现负责；
3. **变更走影响分析**：口径变更前跑 `impact`，同步更新看板、月报、共享接口；
4. **版本化**：口径变更记录版本号与生效日期，历史数据保留 12 个月；
5. **可复核**：每个指标都能从 DWD 明细重算，报告中的数字与 SQL 结果一致。

## 4. 指标与质量的关系

指标不准，往往不是 SQL 写错，而是底层数据质量问题：

| 指标 | 受哪些质量问题影响 |
| --- | --- |
| 市场主体总数 | 信用代码重复、状态码非标准、主体被错误隔离 |
| 活跃率 | 状态码映射错误、注销/吊销数据未同步 |
| A 级信用占比 | 等级与评分不一致、评分越界、评级日期未来 |
| 诉求办结率 | 状态码非标准、办结时间缺失、工单无法关联主体 |
| 平均满意度 | 满意度越界、未回访被误填 0 |

所以本项目先做质量治理，再算指标；指标结果与质量报告互相印证。

## 5. 当前边界

- 信用 A 级占比按记录计算，未按企业最新评价去重；
- 活跃率未剔除长期停业但状态仍为“存续”的主体；
- 满意度未做样本量与显著性检验；
- 指标未做同比/环比，因为只有单期快照。

这些会在接入历史快照后补齐。
