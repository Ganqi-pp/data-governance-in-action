# 运行手册与复盘

> 本文件面向“拿到仓库的人”：怎么跑、会生成什么、怎么验证、遇到问题怎么排查，以及这个项目哪里还不够好。

## 1. 环境要求

| 项 | 要求 |
| --- | --- |
| Python | 3.10+（开发环境 3.13.5） |
| 第三方包 | **无**（仅标准库：sqlite3、csv、json、re、pathlib、argparse、html、math） |
| 操作系统 | Windows / Linux / macOS 均可（CI 在 Ubuntu 上跑） |
| 磁盘 | < 50 MB（含报告、数据、截图） |
| 浏览器 | 任意现代浏览器，用于打开 `reports/dashboard.html` |

## 2. 快速运行

```bash
git clone https://github.com/Ganqi-pp/data-governance-in-action.git
cd data-governance-in-action
python run_demo.py
```

Windows PowerShell 同理；如果终端中文乱码，可设置：

```powershell
$env:PYTHONIOENCODING = "utf-8"
```

运行约 1 秒，终端最后输出：

```text
综合健康度：72.20 -> 90.91
规则达标率：40.9% -> 88.6%
数据可用率：94.4%
问题修复：428 条；待整改：106 条
规则检出率：97.5%
```

## 5. 运行顺序（为什么不能乱）

```text
seed_data.generate
  → db.load_raw / load_reference
  → standards.check
  → quality.baseline（ODS）
  → cleanse（生成 DWD + 隔离区）
  → metadata（ODS + DWD）
  → classify（扫描 ODS 正文 + 从 DWD 导出脱敏）
  → quality.finalize（DWD 复检 + 闭环 + 有效性）
  → lineage / assets / metrics
  → report / dashboard
```

关键点：

- **基线必须在清洗前**，否则没有“治理前”；
- **分类分级在清洗后**，因为共享导出依赖 DWD；
- **质量复检在分类分级后**，因为需要读取隔离区；
- **资产依赖质量分与血缘**，所以放在最后；
- **报告依赖所有 JSON**，最后生成。

## 6. 测试与验收

### 6.1 单元测试

覆盖：

- GB 32100 校验位（正确/错误/长度/字符集）；
- 手机号归一（分隔符、+86、全角、非法）；
- 日期解析（ISO、斜杠、点、紧凑、非法、未来）；
- 脱敏函数（姓名、手机、邮箱、身份证、银行卡、地址）；
- 配置一致性（规则 ID 唯一、字段存在、级别合法、码表可解析）；
- 产物一致性（质量提升、检出率、残留 0、资产完整率、问题状态合法）。

### 6.3 CI

`.github/workflows/ci.yml` 在 Python 3.10 / 3.12 上：

1. checkout；
2. `python run_demo.py`；
3. `python -m unittest discover -s tests -v`；
4. `python run_demo.py verify`；
5. 上传 `reports/` 产物。

任何一步失败都会红灯。

## 7. 常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `ModuleNotFoundError: dgov` | 不在仓库根目录运行，或未用 `run_demo.py` | `cd` 到仓库根目录，用 `python run_demo.py` |
| 终端中文乱码 | Windows 控制台编码 | `$env:PYTHONIOENCODING="utf-8"` |
| 驾驶舱打开空白 | 浏览器禁用了 JS | 允许 JS；或看 `quality_report.md` |
| 报告数字与 README 不一致 | 重新造数/改配置后未同步 README | 以 `reports/quality_result.json` 为准，更新 README |
| `sqlite3.OperationalError: no such table` | 手动删了 `warehouse.db` 后只跑了部分命令 | 重新执行 `python run_demo.py` |
| 中文文件名在 Linux 乱码 | 编码环境 | 文件均为 UTF-8，设置 `LANG=C.UTF-8` |
| 想换数据域 | 只改造数脚本不够 | 同步改 standards、rules、classification、assets、lineage、metrics |

## 8. 复盘：哪些做得好，哪些不够

### 8.1 做得好的

1. **闭环完整**：从标准到资产，六项能力都有代码和产物，不是只有文档；
2. **可验证**：缺陷清单 + 检出率 + 同主键复检，能证明“规则有效、问题修了”；
3. **诚实**：保留 106 条待整改、198 条隔离、1 类未覆盖，写清边界；
4. **可复现**：零依赖、固定种子、一条命令、CI 重跑；
5. **可展示**：驾驶舱、报告、模板、面试讲法齐全，适合作为求职作品。

### 8.2 不够好的

| 问题 | 影响 | 改进 |
| --- | --- | --- |
| 语义质量未覆盖 | 名称截断、地址错别字发现不了 | 引入外部核验/人工抽检/大模型辅助 |
| 血缘靠配置 | 可能与实际 SQL 漂移 | 解析 SQL 或接 DataHub/Atlas |
| 单期快照 | 看不到趋势 | 增加历史快照与月度对比 |
| 信用 A 级占比未按企业最新评价去重 | 指标口径偏差 | 增加评价期次与最新记录逻辑 |
| 安全控制是示例 | 不能直接上生产 | 接权限网关、动态脱敏、密钥管理 |
| SQLite 性能有限 | 大数据量跑不动 | 换数仓/Spark，规则 SQL 平移 |
| 规则容差是人为设定 | 可能与业务 SLA 不一致 | 与业务共同评审，按季度校准 |

### 8.3 如果重做

1. 先定指标和标准，再写清洗；指标会倒逼标准，标准会倒逼规则；
2. 更早做历史快照，质量治理没有趋势就没有管理；
3. 把隔离数据工单化，而不是只写原因码；
4. 更早接 CI，避免“本地能跑、提交就坏”；
5. 把“业务收益”作为下一阶段目标，而不是只看质量分。
