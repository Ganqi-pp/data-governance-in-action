# 数据治理章程

> 版本：V1.0　生效日期：2026-08-01　适用范围：电商业务数据域（交易、用户、商品、渠道、履约、营销）

## 第一章 总则

**第一条 目的**
为规范公司数据资产管理，提升数据准确性、完整性与安全性，让数据成为可复用、可审计、可度量的资产，特制定本章程。

**第二条 依据**
《数据安全法》《个人信息保护法》《数据管理能力成熟度评估模型（DCMM）》及公司信息安全管理制度。

**第三条 适用范围**
适用于各业务系统产生的订单、用户、商品、渠道、履约、营销等数据，覆盖采集、存储、加工、共享、归档、销毁全生命周期。

## 第二章 组织与职责

| 角色 | 职责 |
| --- | --- |
| 数据治理委员会 | 审批治理规划、标准与重大变更；裁决跨域数据争议；季度听取治理报告 |
| 数据 Owner（按域设置） | 对本域数据的准确性、完整性与安全性负责；审批标准与质量规则；牵头问题整改 |
| 数据管家（Data Steward） | 维护数据字典与指标口径；执行日常巡检；跟踪整改台账 |
| 数据开发 | 按标准建模与开发；修复上游缺陷；保障任务 SLA |
| 数据安全官 | 组织分类分级、权限审批与合规审计 |
| 数据分析师 | 按统一口径取数；反馈口径问题；参与规则评审 |

## 第三章 治理域与运行机制

**第四条 治理域**
数据标准、元数据与数据目录、数据质量、数据安全与分类分级、数据资产、数据血缘六大域，由数据治理委员会统一规划。

**第五条 标准管理**
新增表、字段、指标必须先提交标准申请，经数据 Owner 评审后发布；命名、类型、码值必须符合《数据标准管理办法》。未通过标准检查的模型不得上线。

**第六条 元数据与目录**
所有上线表必须在数据目录完成登记，包含表级描述、字段业务含义、Owner、更新频率、SLA。缺失登记的表视为未上线。

**第七条 质量与整改**
按完整性、唯一性、有效性、一致性、及时性五个维度配置质量规则；每日巡检，失败即生成问题单，按 SLA 派单、整改、复检、关闭，形成闭环。

**第八条 安全与分级**
按 L1—L4 四级分类分级，L3/L4 字段必须脱敏展示并纳入访问审批；L4 数据访问需留痕审计，每季度复核权限。

**第九条 资产与血缘**
核心表须登记为数据资产，明确 Owner、密级、更新频率、使用场景；表级血缘由作业配置与 SQL 解析自动生成，变更前必须做影响分析。

## 第四章 考核与问责

**第十条 质量考核**
数据质量分纳入数据 Owner 月度考核，核心表质量分低于 99.5 视为亚健康；连续两个月未达标需提交专项整改方案。

**第十一条 红线**
以下行为视为治理红线：绕过标准私建表、未登记即对外供数、私自导出 L4 数据、篡改质量监控结果。违者按公司信息安全制度处理。

## 第五章 附则

**第十二条** 本章程由数据治理委员会负责解释，自发布之日起施行，每半年评审一次。
