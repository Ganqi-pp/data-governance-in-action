# 数据质量责任矩阵（RACI）

> R = 负责执行　A = 最终问责　C = 需咨询　I = 需知会

## 一、角色定义

| 代号 | 角色 | 说明 |
| --- | --- | --- |
| DO | 数据 Owner | 按业务域设置，对数据质量结果负最终责任 |
| DS | 数据管家 | 维护标准与规则，执行巡检与问题跟踪 |
| DE | 数据开发 | 负责清洗作业、修复上游缺陷 |
| DA | 数据分析师 | 使用数据、反馈口径与质量问题 |
| SEC | 数据安全官 | 负责分级、权限与合规审计 |
| BIZ | 业务方 | 提供业务规则与验收标准 |

## 二、RACI 矩阵

| 治理活动 | DO | DS | DE | DA | SEC | BIZ |
| --- | --- | --- | --- | --- | --- | --- |
| 数据标准制定 | A | R | C | C | I | C |
| 元数据与目录登记 | A | R | C | I | I | I |
| 数据质量规则设计 | A | R | C | C | I | C |
| 日常质量巡检 | I | R | C | I | I | I |
| 问题定位与派单 | A | R | C | I | I | I |
| 上游缺陷修复 | I | C | R | I | I | I |
| 整改验收与关闭 | A | R | C | C | I | C |
| 分类分级与脱敏 | A | C | C | I | R | I |
| 数据资产登记 | A | R | C | I | C | I |
| 权限审批（L3/L4） | A | I | I | I | R | I |
| 变更影响分析 | A | R | C | I | C | I |
| 季度治理复盘 | A | R | C | C | C | I |

## 三、问题分级与 SLA

| 级别 | 判定标准 | 整改时限 | 升级机制 |
| --- | --- | --- | --- |
| P0 | 影响资金/对外披露，或 L4 数据泄露 | 4 小时 | 立即上报数据治理委员会 |
| P1 | 核心表质量分 < 99，影响日报/经营决策 | 24 小时 | 超时升级至域负责人 |
| P2 | 单条规则失败率 < 2%，影响局部分析 | 3 个工作日 | 周会通报 |
| P3 | 命名/元数据等规范类问题 | 下周迭代 | 月度通报 |

## 四、闭环要求

1. 每个问题必须有唯一编号、责任人、期限、样本数据；
2. 修复后必须复跑规则并留存复检结果；
3. 同类问题一个月内重复出现 2 次以上，须升级为流程改进项，补充规则或校验前移；
4. 整改台账每月归档，纳入数据 Owner 考核。
