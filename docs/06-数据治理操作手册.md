# 数据治理操作手册

> 面向数据开发与数据管家的操作指南，覆盖「建表 → 登记 → 配规则 → 巡检 → 整改 → 下线」全流程。

## 一、新表接入

1. **建模评审**：按《数据标准管理办法》命名，确定分层、业务域、Owner、更新频率；
2. **建表**：在 `sql/schema.sql` 增加 DDL，字段必须带业务含义；
3. **登记元数据**：在 `config/business_metadata.json` 补充表描述与字段中文名；
4. **登记资产**：在 `config/assets.json` 增加资产条目（Owner、密级、SLA、使用场景）；
5. **跑标准检查**：`python run_demo.py` 后查看 `reports/standard_check.md`，违规项清零后方可上线。

## 二、质量规则配置

规则统一维护在 `config/quality_rules.json`，支持 6 种类型：

| 类型 | 用途 | 关键参数 | 示例 |
| --- | --- | --- | --- |
| `unique` | 主键/业务键唯一 | 字段 | `order_id` 唯一 |
| `not_null` | 关键字段非空 | 字段 | `create_time` 非空 |
| `enum` | 码值合法 | `values` | 订单状态 7 个标准值 |
| `regex` | 格式校验 | `pattern` | 手机号 `^1[3-9]\d{9}$` |
| `expression` | 业务规则/一致性 | `expr` | `pay_amount >= 0` |
| `referential` | 外键可关联 | `ref_before_table` / `ref_after_table` | 商品 ID 必须存在 |
| `freshness` | 时效性 | `max_lag_hours` | 下单时间不得超前 |

新增规则示例：

```json
{
  "id": "DQ-ORD-015",
  "dataset": "order",
  "column": "coupon_amount",
  "name": "优惠金额不超过订单金额",
  "dimension": "一致性",
  "type": "expression",
  "severity": "medium",
  "owner": "订单域数据 Owner",
  "sla_hours": 48,
  "params": {"expr": "coupon_amount <= order_amount"}
}
```

## 三、巡检与复检

- 治理前基线：对 ODS 表执行规则，得到质量基线；
- 治理后复检：对 DWD 表执行同一套规则，验证清洗效果；
- 输出：`reports/quality_report.md`、`reports/quality_summary.json`、`reports/dashboard.html`；
- 建议接入调度系统每日 08:00 执行，失败即推送告警。

## 四、问题整改闭环

1. 规则失败 → 自动生成问题单（编号、责任人、SLA 期限、样本数据）；
2. 责任人定位上游：按血缘表找到直接上游作业与源系统；
3. 修复后重跑规则，复检通过后关闭问题单；
4. 同类问题重复出现 2 次以上，触发流程改进（校验前移或新增规则）。

## 五、变更与下线

- 字段/码值变更：先做血缘影响分析，通知下游，灰度发布；
- 表下线：提前 15 天公告，确认无下游依赖后归档，资产状态置为「已下线」；
- 所有变更记录在 `docs/` 与 Git 提交历史中，保证可追溯。

## 六、常见问题

| 问题 | 排查思路 |
| --- | --- |
| 质量分突然下降 | 检查上游是否新增字段/改码值；对比昨日规则失败明细 |
| 重复订单 | 检查订单库是否重复推送；核对 `order_id` 生成规则 |
| 渠道为 UNKNOWN | 检查渠道映射表是否覆盖新渠道；补码值后重跑清洗 |
| 手机号大量为空 | 检查上游是否加密或格式变更；确认脱敏是否误伤 |
| 报表口径不一致 | 对照《指标口径字典》，确认是否使用了旧口径 |
