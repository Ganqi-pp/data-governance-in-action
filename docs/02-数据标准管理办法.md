# 数据标准管理办法

> 版本：V1.0　归口部门：数据治理小组　适用对象：数据开发、数据分析、数据产品

## 一、命名规范

| 对象 | 规则 | 示例 | 反例 |
| --- | --- | --- | --- |
| 表名 | `分层前缀_业务域_主题`，全小写下划线 | `dwd_order_detail` | `OrderDetail`、`order_detail_v2` |
| 字段名 | 全小写下划线，禁止驼峰与拼音 | `pay_amount` | `payAmount`、`je` |
| 分区字段 | 统一 `dt` 或 `order_date` | `order_date` | `day`、`d` |
| 指标编码 | `业务域_指标_统计周期` | `trade_gmv_day` | `GMV1` |
| 分层前缀 | `ods` 贴源、`dwd` 明细、`dws` 汇总、`dim` 维度、`ads` 应用 | `dws_channel_daily` | `tmp_xxx` 上线 |

## 二、数据类型规范

1. 金额统一 `REAL/NUMERIC`，单位元，保留两位小数；
2. 时间统一 `TEXT`，格式 `YYYY-MM-DD HH:MM:SS`，禁止混用时间戳与字符串；
3. 枚举字段使用标准码值，禁止自由文本；
4. 布尔字段统一 `INTEGER`（0/1），禁止 `Y/N` 与 `true/false` 混用。

## 三、码值管理

- 码值由业务域 Owner 提出申请，经数据治理小组评审后发布；
- 码值变更遵循「新增可兼容、修改需评估、废止先迁移」原则；
- 码值清单统一维护在 `config/standards.json`，由标准检查脚本自动校验；
- 禁止在 SQL 中硬编码码值，需通过维表关联。

当前受控码值：订单状态、渠道编码、会员等级、商品状态。

## 四、指标口径管理

1. 每个指标必须有唯一编码、业务定义、计算公式、数据来源、统计周期、责任人；
2. 指标口径变更需提前 3 个工作日公告，并同步更新《指标口径字典》；
3. 同一指标只允许一个官方口径，历史口径保留版本号与失效日期。

## 五、变更流程

```
提出申请 → 影响分析（血缘）→ 数据 Owner 评审 → 试运行 → 发布公告 → 旧版本下线
```

涉及 L3/L4 字段的变更，必须增加数据安全官审批。

## 六、检查与工具

标准检查已脚本化（`src/dgov/standards.py`），覆盖表/字段命名、数据类型、码值一致性、元数据完备性四类规则；检查结果输出至 `reports/standard_check.md`，违规项须在 3 个工作日内整改。

## 七、例外管理

确有历史原因无法整改的，需提交例外申请，注明原因、影响范围与退出计划，经数据治理委员会审批后进入例外清单，每季度复审。
