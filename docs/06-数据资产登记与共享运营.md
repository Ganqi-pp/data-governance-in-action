# 数据资产登记与共享运营

> 数据资产不是“一张表”，而是“有 Owner、有分级、有质量、有血缘、有使用场景、可被审计”的数据产品。
> 本项目登记 15 项资产，覆盖源表、明细表、指标、共享接口、码表和报告。

## 1. 什么算数据资产

同时满足以下条件才登记：

1. 有明确的业务用途和消费方；
2. 有数据 Owner 和 Steward；
3. 有分级、共享属性和更新频率；
4. 有质量评估结果；
5. 能追溯到来源和下游。

临时表、测试表、一次性导出文件不登记。

## 4. 资产分级与共享策略

| 共享属性 | 适用对象 | 控制措施 |
| --- | --- | --- |
| 公开 | L1 指标、码表 | 发布前一致性校验，保留发布记录 |
| 内部共享 | L1/L2 报告、看板 | 按角色授权，禁止外传 |
| 有条件共享 | L2/L3 明细、接口 | 申请—Owner 确认—安全审批—脱敏—日志 |
| 脱敏共享 | 含个人信息的数据 | 脱敏、残留扫描、接收方承诺、到期回收 |
| 不共享 | ODS 原始表、L4 | 仅授权人员可访问，禁止出域 |

原则：**同意的资产才能共享，共享的字段必须最小必要，含个人信息的必须脱敏并留痕。**

## 5. 价值评估

每季度从四个维度评估：

| 维度 | 指标 | 权重 |
| --- | --- | ---: |
| 使用频次 | 近 90 天访问/调用次数 | 30% |
| 支撑业务 | 支撑的业务场景/报表数量 | 30% |
| 质量 | 最近一次质量分 | 25% |
| 共享收益 | 对外共享/复用带来的业务价值 | 15% |

评估结果分为 A（重点运营）、B（正常维护）、C（观察）、D（归档候选）。连续两个季度 D 且无业务依赖的资产，经 Owner 确认后归档。

## 6. 运营流程

```mermaid
flowchart LR
    A[上线/发布前登记] --> B[Owner 确认]
    B --> C[Steward 补全要素]
    C --> D[质量评估]
    D --> E[发布资产卡片]
    E --> F[使用与反馈]
    F --> G[季度价值评估]
    G --> H{继续运营?}
    H -- 是 --> E
    H -- 否 --> I[归档/下架]
```

### 新增

系统上线或数据产品发布前 5 个工作日提交登记；未登记不得共享。登记信息与标准、血缘、质量结果自动关联，减少手工填写。

### 变更

表结构、口径、Owner、共享范围变化时同步更新台账；变更前跑影响分析，变更后重跑质量与指标。

### 下架

连续 6 个月无访问且无业务依赖，经 Owner 确认后归档；归档资产保留元数据与血缘，不再提供访问。

## 7. 共享接口示例

### 市场主体共享接口（DA-010）

- 来源：`dwd_market_register`
- 字段：企业名称、信用代码、区划、行业、状态、注册资本、注册日期；姓名/电话/邮箱/地址脱敏；
- 更新：每日；
- 消费方：政务服务大厅、数据共享交换平台；
- 控制：申请审批、最小字段、日志留存、季度复核。

### 企业诉求共享接口（DA-011）

- 来源：`dwd_complaint_case`
- 字段：工单号、类型、提交时间、承办部门、状态、满意度、脱敏正文；
- 更新：每日；
- 消费方：营商环境分析、政务服务优化专班；
- 控制：正文按识别结果脱敏，残留扫描 0 后才可交付。

## 8. 审计与考核

| 审计项 | 频率 | 责任 |
| --- | --- | --- |
| 台账与库表/接口一致性 | 半年 | 数据 Steward |
| 共享授权与日志 | 季度 | 安全合规岗 |
| 资产价值评估 | 季度 | 数据 Owner |
| 未登记资产清查 | 季度 | 数据 Steward |
| 下架资产清理 | 半年 | 数据 Owner |

考核指标：登记完整率 100%、有 Owner 比例 100%、共享审批合规率 100%、季度评估完成率 100%。

## 9. 当前边界

- 资产台账是本地 JSON/CSV，不是企业级数据资产平台；
- 价值评估是方法示例，没有真实访问日志与收益数据；
- 共享接口是脱敏文件，不是带鉴权、限流、审计的 API 网关；
- 未实现资产血缘的自动发现，仍依赖配置。

这些能力可以在接入 DataHub/Atlas、API 网关、调度平台后逐步补齐。
